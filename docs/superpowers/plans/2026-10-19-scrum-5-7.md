# SCRUM-5 and SCRUM-7 implementation plan

**Goal:** Centralize .NET build conventions and complete the SQL-first migration/scaffold workflow.

**Architecture:** Keep the existing six production projects, four test projects and standalone migrator. Use SDK artifacts output and the official EF Core CLI/provider; generated persistence code stays in Infrastructure. Work in the current clean development checkout; do not stage docs or change applied SQL.

## Task 1 — Shared build conventions

- [x] Add a repository-conventions check to the existing Domain test project.
- [x] Add `server/Directory.Build.props`: C# 14, nullable/implicit usings, .NET 10 recommended analyzers, warnings as errors, deterministic builds and root `artifacts/` output.
- [x] Include shared props in the migrator Docker build and ignore build/coverage/IDE artifacts.
- [x] Verify with `dotnet build server/TempoDesk.sln` and `dotnet test server/TempoDesk.sln --no-build` (Debug and Release).

## Task 2 — Scaffold workflow

- [x] Pin local `dotnet-ef` and EF Design 10.0.10; use Npgsql EF provider 10.0.3 in Infrastructure only.
- [x] Add `database/scaffold.sh`: require an explicit table allowlist, use PGPASSWORD, generate context/entities only under `Persistence/Generated`, and omit OnConfiguring.
- [x] Extend the isolated database test to scaffold a probe in a temporary copy of the source, compile it, and assert generated paths and absence of credentials.
- [x] Document migrations/functions/views/seeds and the scaffold command; add a minimal foundation CI job running the same checks without repository secrets.
- [x] Run migration/scaffold tests on temporary resources, verify no tracked artifacts/secrets, and review the diff. Do not commit unless requested.

## Verification findings

- The conventions test failed before shared props existed, then passed after implementation.
- Recommended analyzers exposed a locale-sensitive port parser; fixed with invariant culture.
- EF metadata discovery on a clean source tree requires explicit project restore before scaffolding.
- Fresh Docker bootstrap exposed an interpreter permission failure in the old shell init script. Replaced it with native psql `init.sql` and a bind mount that refuses missing host files.
- The complete migration/scaffold check passed on both the existing PostgreSQL service and a separately bootstrapped CI-style stack with its own disposable volume and random host port. All test resources were cleaned; the user's database and applied SQL were not changed.
- GitHub workflow was added but not remotely executed; no push/commit was requested.
